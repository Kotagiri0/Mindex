# Декларация: Mindex как технологическая лаборатория

> Написано: 2026-06-11
> Автор: технический агент проекта
> Статус: стратегический документ, не для публикации

---

## Инженерный принцип

**Мы строим внутри AI-архитектуры структуру компьютера.**

- **Процессор** — LLM. Только вычисляет и генерирует ответ.
- **Жёсткий диск** — ПОЛИСАД. Хранит и извлекает память через векторы, без LLM.
- **Сетевой модуль** — РЕЛЬСА. Подключает к внешним данным через станции, без LLM.

Классический компьютер именно так устроен — процессор не хранит данные и не качает интернет сам. Каждый компонент делает своё.

Все остальные AI-продукты сейчас — процессор который одновременно является жёстким диском и сетевой картой. Дорого, медленно, не масштабируется.

**LLM только там где без неё невозможно.** Память, поиск, классификация, фильтрация — математика и детерминированные структуры. На масштабе это даёт 10x преимущество по стоимости и скорости.

---

## Тезис

Mindex — не таск-менеджер с ИИ. Mindex — это первый продукт суверенной российской AI-лаборатории, работающий как полигон для технологий, которые потом продаются отдельно.

Формула: **создаём технологии для своего бизнеса, а не бизнес из технологий.**

Каждая технология сначала появляется внутри продукта, проходит боевую проверку на реальных пользователях — потом оформляется как самостоятельный API. Продукт = полигон. Технологии = побочный продукт боевой разработки.

---

## Почему не враппер — это вопрос выживания

Враппер — это ритейл: перепродаёшь чужое, зависишь от поставщика, конкурируешь ценой, барьер входа нулевой. Любой копирует за неделю.

Свой стек — это промышленность: строишь актив, который работает на тебя, который никто не отберёт, который можно продавать B2B.

Российский рынок особенно уязвим: весь корпоративный сектор сидит на OpenAI/Anthropic через VPN и молится чтобы не отключили. Регуляторный риск огромный. Своего игрока уровня "исследовательская лаба с продуктами" в России нет.

## Технологический стек лаборатории

### 1. ПОЛИСАД — система персональной памяти для AI-агентов
**Статус: работает в проде, требует оформления**

Долгосрочный контекст + RAG + профиль пользователя + авто-саммаризация, заточенные под личное использование.

Это продаваемый примитив. То, чего нет в коробке ни у одного провайдера — память агента, которая персонализируется от пользователя к пользователю и умнеет со временем.

**Текущее состояние:**
- Векторный поиск по саммари прошлых тредов (cosine similarity > 0.65)
- Keyword fallback если vector miss
- Профиль пользователя всегда в промпте
- Авто-саммаризация при закрытии треда
- Эмбеддинги хранятся в PostgreSQL через pgvector

**Что нужно сделать:**
- Выделить в отдельный модуль `src/polisad/` с чистым API
- Определить публичный контракт: `getContext(userId, query)`, `summarize(threadId)`, `storeMemory(userId, content)`
- Добавить метрики: RAG hit rate, средняя similarity, % тредов с summary, время retrieval
- Дашборд с живыми показателями

---

### 2. РЕЛЬСА — внешняя шина данных / маршрутизатор знаний
**Статус: архитектура готова, реализация предстоит**

Ключевая идея: веб-страница как источник знаний стоит 50-70к токенов. Станция РЕЛЬСА — это заранее написанный JSON-шаблон (CSS-селекторы) для конкретного домена, который компрессирует любой запрос к этому сайту до 500 токенов.

Маршрутизатор получает intent + entities от агента → находит подходящую станцию → fetchHTML → applySelectors → normalizeJSON → возвращает 500-токенный структурированный ответ.

**Аналогия:** браузер как динамический срез данных. Модель не хранит знания в параметрах — она запрашивает их в момент необходимости.

**Компоненты:**
- Station Registry — реестр доменов и их схем
- Station Router — маршрутизация запроса на станцию
- HTML Extractor — raw fetch + CSS-селекторы
- Schema Normalizer — compressToJSON

**Что нужно сделать:**
- Прототип с 3-5 станциями (habr.com, vc.ru, документация)
- Выделить в `src/relsa/`
- Метрики: токенов сэкономлено, станций в реестре, cache hit rate

---

### 3. Маршрутизатор моделей
**Статус: зачаток в проде (RouterAI + OpenRouter fallback)**

Уже работает: primary → fallback на 401/5xx/timeout. Это seed будущего полноценного роутера.

**Что нужно сделать:**
- Выделить в `src/router/`
- Добавить cost-aware routing: дешёвые запросы → маленькая модель, сложные → большая
- Метрики: % primary vs fallback, latency by model, error rate, стоимость на запрос

---

### 4. Sreda LLM — гибридная непараметрическая архитектура
**Статус: концепция, реализация после оформления предыдущих трёх**

Архитектура "Матрикс":
- **Dry LLM 1-3B** — базовая модель на VPS (Ollama + Qwen2.5 или аналог). Несёт reasoning, не knowledge.
- **ПОЛИСАД** — личная память пользователя
- **РЕЛЬСА** — живые знания из веба

Метафора: MSFS 2024. Движок (Dry LLM) фиксированный, мир (знания) стримится по мере необходимости. Параметры = интеллект. Знание = внешнее, живое, обновляемое без переобучения.

Это не "своя LLM" в смысле pretraining с нуля. Это своя **архитектура** на базе открытых моделей. Честное название: **гибридная непараметрическая LLM-система**.

**Шаги к реализации:**
1. Поднять Ollama на VPS, протестировать Qwen2.5-1.5B / 3B
2. Подключить как дополнительный backend в маршрутизаторе
3. Направить на него простые запросы (классификация, краткие ответы)
4. Постепенно расширять зону ответственности по мере роста качества

## Как это оформляется наружу

**Страница "Технологии" на сайте** — как Research у OpenAI. Каждая технология = отдельный раздел с описанием, архитектурой, метриками.

**Цель:** не маркетинг, а сигнал рынку. "Мы лаб, у нас есть что продавать B2B отдельно от продукта."

**Когда это станет правдой:**
- Опубликованы технические описания ПОЛИСАД и РЕЛЬСА
- Хотя бы один внешний разработчик использует API
- Есть публичные метрики эффективности

## Почему это сработает именно сейчас

1. **Рынок не занят.** Яндекс — корпорация с другими приоритетами. Остальные — враперы или академия без продукта.
2. **Государственный момент.** РФРИТ, Сколково, федеральные медиа активно ищут истории про импортозамещение в ИИ. 17-летний основатель строящий суверенный стек — это история которую напишут сами.
3. **Продукт уже есть.** Технологии не в вакууме — они в проде, на реальных пользователях. Это принципиальное отличие от академических проектов.
